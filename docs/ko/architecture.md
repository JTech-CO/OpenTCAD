## 현재 실행 경로

| 경로 | 구현 | 실행 경계 |
|---|---|---|
| 브라우저 계산기 | React와 코드로 정의한 NMOS 해석식 모델 | GitHub Pages를 포함한 브라우저에서 실행 |
| 참조 작업공간 | 설명용 프로젝트와 결과 확인 UI | 솔버 요청 없이 모의 실행만 제공 |
| 실험용 실험실 | 인증된 loopback HTTP와 고정 네이티브 DEVSIM 템플릿 | 명시적 PN·2D MOS 실행, 동시 해석 하나 |
| Windows 로컬 MVP | 실험실과 독점 SQLite 기록, 복구·오프라인 백업 | Windows 프로세스 격리, 고정 템플릿만 실행 |
| SUPREM 공정 CLI | 명시적 네이티브·로컬 컨테이너 실행과 구조·전극 전달 | 신뢰하는 사용자의 별도 활성화, 브라우저 덱 실행 API 아님 |
| M3 OCI 제품 | 브로커, 런타임 어댑터와 증거 기반 릴리스 프로필 | 별도로 구현되어 있으며 활성화 차단 |

웹 인터페이스를 공유하지만 모든 보장을 공유하지는 않습니다. 현재 실험실은 M3 샌드박스 브로커가 아닙니다. 다중 사용자 공유 솔버 서비스는 구현되지 않았습니다.

## 실험실 데이터 흐름

브라우저는 상한이 있는 숫자 입력을 동일 출처의 loopback API로 보냅니다. 서비스는 고정 솔버 워커를 시작하고 작업 상태와 검증된 결과 레코드를 반환합니다. 업로드한 Python, 셸 명령이나 임의 공정 덱을 받지 않습니다. 실패한 솔버 출력을 해석식이나 참조 데이터로 대체하지 않습니다.

서비스는 실행마다 개인용 URL 조각을 발급합니다. 브라우저는 이를 읽고 주소에서 제거하며 토큰을 메모리에만 보관합니다. 새로고침 후 원래 개인용 주소를 다시 열면 연결할 수 있습니다. 토큰을 공유하거나 프로젝트·결과 파일에 저장하면 안 됩니다.

Windows MVP는 상태 폴더의 독점 소유, SQLite 이력, 서비스·런처 종료 시 정리와 재시작 시 중단 판정을 추가합니다. 백업은 오프라인 체크섬 검증이며 인증·암호화가 아닙니다. 같은 사용자 권한으로 파일에 접근하는 악성 프로세스를 막거나 물리적 전원 차단 내구성을 보장하지 않습니다. [Windows 운영 안내](windows-mvp.md)를 참고하세요.

## 공정 전달과 자동화

SUPREM은 별도로 설치한 신뢰 가능한 솔버를 명시적 CLI로 실행합니다. 소자 서비스는 시작 시 지정된 공정·전극 파일을 읽고 지원 구조를 검사한 뒤 고정 스냅샷을 사용합니다. 도핑만 전달하는 모드와 원본 메시 전달은 다릅니다. [공정 연계](mos-process.md)와 [메시 전달](process-mesh.md)을 참고하세요.

[stdio MCP 연결기](mcp.md)는 같은 인증된 숫자 loopback 서비스에 연결합니다. 기본은 읽기 전용입니다. 명시적 실행 권한으로 고정 PN·MOS 요청과 취소를 제공하지만 임의 스크립트·경로와 자동 스윕 대기열은 제공하지 않습니다.

## 별도 M3 트랙

증거 기반 OCI 제품에는 영속 소유권·fencing, 브로커, Docker·Podman 어댑터, 자격 증명 연계와 유지보수·백업 계약이 있습니다. 커밋된 릴리스 프로필은 비어 있습니다. 제품 명령은 부수 효과 전에 활성화를 거부하며 매니페스트 변경만으로 활성화되지 않습니다.

이 계약과 더 엄격한 런타임 검증은 별도 트랙으로 보존하며 현재 로컬 MVP의 보장으로 표현하지 않습니다. [M3 서비스](m3-local-service.md)를 참고하세요. 사용자 문서를 정리하면서 해당 검사를 삭제하거나 런타임 권한을 부여하지 않습니다.

## 코드 담당 영역

- `frontend/src/mvp/`: 계산기, 실험실과 결과 이력 UI
- `backend/app/experimental/`: 고정 PN·MOS 워커, 공정 전달, Windows MVP와 MCP
- `backend/app/product/`, `runtime/`, `broker/`, `service/`: 별도로 차단된 OCI 서비스와 계약
- `validation/`: 수치 관측, 증거와 계약 검사
- `docs/en/`, `docs/ko/`: 한영 사용자·유지보수 안내

정적 자산에는 네이티브 솔버가 없습니다. 참조 데이터, 해석식 추정, 외부 입력과 실제 솔버 결과는 출처 표시를 구분해야 합니다. 내부 구성보다 지원 기능을 알고 싶다면 [시뮬레이션 안내](simulation-guide.md)부터 확인하세요.
