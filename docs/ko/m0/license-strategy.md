# M0 라이선스 전략

[English](../../en/m0/license-strategy.md) | [M0 상태](README.md)

## 현재 적용 결정

OpenTCAD 고유 코드와 새 문서는 MIT로 배포합니다. 현재 공개 산출물은 엔진 없는 정적 빌드입니다. 여기에 SUPREM-IV.GS, 참조 애플리케이션 패치, DEVSIM, Gmsh, 솔버 이미지, 또는 해당 산출물을 가져오거나 조용히 설치하는 installer를 포함하면 안 됩니다.

솔버 배포 결정은 승인된 것이 아니라 차단된 상태입니다. 이 명시적 M0 결과로 검토되지 않은 혼합 라이선스 릴리스를 방지합니다.

## 증거

- OpenTCAD 저장소에는 루트 `LICENSE`와 `NOTICE`가 있습니다.
- 고정된 참조 애플리케이션에는 애플리케이션 코드 복사를 허가하는 루트 라이선스가 없습니다.
- 고정 참조 commit의 `SUPREM4GS/upstream/LICENSE`는 Stanford 1994 별도 고지입니다. MIT가 아니며 상업 거래 제한 문구가 있습니다.
- 참조 provenance는 `rafael1193/suprem4gs` commit `33e90433a9d1e5134deaa8773f59be37d3256b13`을 가리키며 별도 패치를 적용합니다. 패치의 권리자와 OpenTCAD 배포 권한은 아직 확정되지 않았습니다.
- DEVSIM 공식 저장소는 Apache-2.0을 밝히고 NOTICE를 포함합니다.
- Gmsh 공식 문서는 Gmsh 예외가 있는 GPL version 2 이상을 밝힙니다.
- 참조 이미지 tag는 가변이며 운영체제 전이 패키지를 포함합니다. tag 이름만으로 라이선스와 재현성 증거가 되지 않습니다.

Hash와 정확한 selector는 [`m0/DEPENDENCY_AND_IMAGE_INVENTORY.json`](../../../m0/DEPENDENCY_AND_IMAGE_INVENTORY.json)에 기록합니다.

## 후보 배포 모델

| 모델 | 현재 상태 | 승인 조건 |
|---|---|---|
| A. 혼합 라이선스 소스와 사전 빌드 이미지 | 차단 | 모든 구성 요소, 패치, 고지, 소스 제공 의무, 이미지 SBOM의 전문가 검토 |
| B. 사용자가 제공하거나 로컬에서 빌드하는 선택형 엔진 | 선호하는 임시 방향, 미승인 | OpenTCAD 스크립트와 안내가 제한 산출물을 재배포하지 않으며 엔진이 없을 때 안전하게 실패하는지 확인 |
| C. 권리자 허가 기반 번들 | 대기 | 목표 소스, 바이너리, 이미지, installer, 상업 환경을 포함하는 서면 허가 |
| 엔진 없는 정적 릴리스 | 승인 | 자동화된 무솔버 경계와 제3자 고지를 최신 상태로 유지 |

모델 B는 MIT 애플리케이션 경계를 유지하므로 공학적으로 선호하지만 법률 승인을 뜻하지 않습니다.

## 릴리스 규칙

1. OpenTCAD 고유 코드, 통합 adapter, 문서는 루트 MIT 라이선스로 유지합니다.
2. 제3자 라이선스 원문, 고지, provenance, 패치, 소스 제공 자료를 의무가 발생하는 산출물과 함께 둡니다.
3. 모든 릴리스 이미지를 digest로 고정하고 정확한 빌드 이미지에서 SBOM과 패키지 라이선스 보고서를 생성합니다.
4. 알 수 없는 라이선스, 가변 이미지, 누락된 NOTICE, 누락된 출처를 릴리스 실패로 처리합니다.
5. 배포 제한을 우회하는 수단으로 런타임 다운로드를 사용하지 않습니다.
6. MIT 라이선스가 솔버, 업스트림 예제, screenshot, manual, patch를 재허가한다고 표현하지 않습니다.
7. 솔버 기반 공개 릴리스 전에 maintainer와 전문가가 최종 모델을 기록해야 합니다.

## 미결정 항목

- SUPREM 고지가 의도한 비상업 및 상업 OpenTCAD 배포 경로를 허용하는지 여부
- 참조 패치의 권리자와 OpenTCAD이 그 동작을 재현하거나 대체할 수 있는 조건
- DEVSIM 2.10.1 wheel의 추가 고지 또는 포함 라이브러리
- 각 릴리스 이미지에 포함될 Debian, Python, Gmsh, OpenBLAS, Redis, PostgreSQL의 정확한 산출물과 라이선스
- installer를 엔진 없이 유지할지, 사용자 제공 소스로 로컬 빌드할지, 승인된 번들을 배포할지 여부
