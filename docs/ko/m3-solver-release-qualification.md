# M3 솔버 릴리스 자격 검증

M3 솔버 릴리스 자격 검증은 조건이 충족되지 않으면 승인하지 않는 증거 검사입니다. 계약 테스트가 통과했다는 사실은 검증기 동작만 입증합니다. 솔버, 이미지, 라이선스 판단 또는 수치 기준선을 승인하지 않습니다.

## 제품용 명령

```console
node tools/check-m3-solver-release.mjs --candidate <reviewed-evidence.json> --root .
```

제품용 CLI에는 계약 테스트 자료를 허용하는 옵션이 없습니다. 명령은 승인된 `release-evidence` 문서만 받습니다. 후보 문서는 `validation/solver-release/schema.json`을 충족해야 하며, 검증기는 객체 구조, 중복 JSON 키, 파일 경로 범위, 일반 파일 여부, 바이트 수, SHA-256 해시를 별도로 검사합니다.

## 필수 증거

1. 소스 식별 정보
   - 모든 소스 커밋은 소문자 16진수 40자 또는 64자여야 합니다.
   - 소스 아카이브, 라이선스 원문, 고지, 대응 소스, 패치 출처, 패치 소유권, 재배포 판단은 바이트 수와 해시로 결속됩니다.
2. 완전한 권리 판단
   - SUPREM-IV.GS 소스와 패치 재배포가 각각 승인되어야 합니다.
   - DEVSIM, Gmsh, 전이 런타임 의무에는 책임 있는 검토가 있어야 합니다.
   - 해결되지 않은 전이 라이선스가 없어야 합니다.
3. 변경 불가능한 다중 플랫폼 이미지
   - 정확한 역할 집합은 `transfer`, `suprem`, `devsim`, `gmsh`입니다.
   - 각 역할에는 `linux/amd64` 매니페스트 하나와 `linux/arm64` 매니페스트 하나가 있어야 합니다.
   - 이미지 및 스캐너 참조에는 digest가 있어야 하고 변경 가능한 태그가 없어야 합니다.
   - 각 CycloneDX SBOM의 subject와 내부 `opentcad:subject-manifest-digest` 속성은 플랫폼 매니페스트 digest와 결속되어야 합니다.
4. 수치 검증 자료
   - SUPREM-IV.GS, DEVSIM, Gmsh에는 각각 검토된 사례 하나가 있어야 합니다.
   - 입력, 예상 결과, 출처, 관측 결과 artifact는 해시로 결속됩니다.
   - 선언된 comparator 및 metric 집합은 결과와 정확히 일치해야 합니다.
   - 허용 오차는 유한한 0 이상의 값이어야 하며, 반복 실행은 최소 5회이고 목록에 없는 경고는 실패로 처리됩니다.
   - 출처 정보는 정확한 입력, 예상 결과, 엔진 역할, 이미지 인덱스, 플랫폼, 플랫폼 매니페스트를 결속해야 합니다.
5. 검토
   - 권리, 재현성, SBOM, 사례, 전체 검증 자료, 최종 릴리스 검토가 책임 있는 검토자에 의해 모두 승인되어야 합니다.
   - 일부만 충족되었거나 차단된 증거는 제품 상태로 전환할 수 없습니다.

## 테스트 자료 경계

`validation/solver-release/fixtures/valid-contract.json`은 의도적으로 `contract-fixture`로 표시되고 예약된 테스트 식별자를 사용합니다. 이 artifact는 모두 합성 자료입니다. 제품 검증기는 이 증거 분류를 거부하며 문서를 제품 증거로 바꾸어 표시해도 테스트 자료 디렉터리의 artifact 경로를 거부합니다.

다음 명령은 계약 동작만 검사합니다.

```console
node --test validation/solver-release/validator.test.mjs
```

법률 허가, 솔버 재배포 권리, 플랫폼 이미지 게시, SBOM 검토, 수치 허용 오차 승인, 최종 릴리스 승인은 외부 담당자의 판단으로 남습니다. 검증기는 그 판단을 기록하고 확인하지만 대신 만들어 낼 수 없습니다.
